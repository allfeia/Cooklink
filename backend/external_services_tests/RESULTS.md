## Util — Сбор видео (YouTube Data API v3)

Скрипт выполнял поиск по русско- и англоязычным кулинарным запросам, фильтровал видео по языку заголовка и продолжительности (не более 15 минут).

**Запросы (RU):** `рецепт`, `быстрый рецепт`, `как готовить`, `ужин рецепт`  
**Запросы (EN):** `recipe`, `easy recipe`, `quick recipe`, `cooking tutorial`

**Результат:** собрано 100 уникальных видео (50 RU + 50 EN), сохранено в `recipes-ru-en.json` и `test-urls-auto.js`.

## Test 1 — Метаданные видео: сравнение инструментов

Тест запускался на 100 URL, все три инструмента показали 100% успешность.

| Инструмент | Успех | Ошибки | Avg, мс | Max, мс |
|---|---|---|---|---|
| **A** — `@distube/ytdl-core` | 100/100 | 0 | 1 076 | 2 101 |
| **B** — `yt-dlp-exec` | 100/100 | 0 | 2 401 | 6 620 |
| **C** — YouTube Data API v3 | 100/100 | 0 | **80** | 161 |

**Вывод:** YouTube Data API v3 быстрее примерно в 13× по сравнению с `ytdl-core` и в 30× по сравнению с `yt-dlp-exec`. Для получения метаданных в продакшене рекомендуется использовать официальный API (Tool C) — он стабильнее, не зависит от внутренней структуры YouTube и не требует бинарных зависимостей. `yt-dlp-exec` целесообразно оставить только там, где нужны данные, недоступные через API (субтитры, форматы потоков).

## Test 2 — Субтитры: yt-dlp

### Что такое yt-dlp

`yt-dlp` — это open-source CLI-инструмент (форк `youtube-dl`) для загрузки видео и метаданных с YouTube и других платформ. В проекте используется через npm-обёртку `yt-dlp-exec`, которая запускает бинарник как дочерний процесс Node.js.

Ключевые возможности, задействованные в тесте:

- `--write-auto-subs` / `--write-subs` — загрузка автоматических и ручных субтитров
- `--sub-langs ru,en` — выбор языков
- `--sub-format vtt` — формат субтитров WebVTT
- `--skip-download` — только субтитры, без видеофайла

После загрузки `.vtt`-файл парсится в plain text (убирается разметка таймкодов и тегов) и сохраняется как `.txt`.

### ⚠️ Проблема с rate limiting (HTTP 429) и её решение

При большом количестве последовательных запросов YouTube начинает возвращать ошибку `429 Too Many Requests` для неавторизованных сессий. В ходе тестирования проблема была решена передачей cookie авторизованного аккаунта YouTube в yt-dlp (`--cookies`).

**Рекомендации для продакшена при высокой нагрузке:**

- **Кэшировать субтитры** после первой загрузки — повторные запросы к одному видео исключить полностью.
- **Очередь с троттлингом** — не запускать более 1–2 параллельных запросов к YouTube, использовать задержку между ними (rate limiter на уровне воркера).
- **Пул аккаунтов / OAuth** — ротировать несколько авторизованных сессий, чтобы распределить нагрузку между аккаунтами.
- **Proxy pool** — при горизонтальном масштабировании маршрутизировать запросы через разные IP-адреса.
- **Fallback** — если субтитры недоступны через yt-dlp, пробовать YouTube Transcript API как резервный вариант; если и он не даёт результата — помечать видео как `no_subtitles` и пропускать на этапе LLM.

## Test 3 — LLM: извлечение рецепта (Qwen)

Субтитры (.txt) отправлялись в модель `qwen-max` с задачей извлечь структурированный JSON рецепта по схеме: название, тип блюда, время приготовления, сложность, порции, ингредиенты, шаги, комментарии.

| Метрика | Значение |
|---|---|
| Файлов на вход | 87 |
| ✅ Валидных рецептов | 60 (69%) |
| ⚠️ Ошибки схемы | 27 (31%) |
| ❌ Ошибки API | 0 |
| Токенов всего | 118 545 |
| Avg время ответа | 6 010 мс |
| Max время ответа | 16 157 мс |

**Вывод:** модель успешно извлекает рецепты в 69% случаев. Ошибки схемы (31%) возникают из-за наложенной музыки в видео или речи, которая не комментирует сам рецепт
